| cross-agent summary | computed, not stored | Built from agent\_observation\_rows by the aggregation layer; the website displays it as computed and never computes it itself. For each Item: Pass only if more than half of the agents that completed the check pass it; Fail if half or fewer pass. |
| cross-agent summary | only completed checks count | An agent that did not complete the check for an Item — interrupted, or a tool it needed was unavailable — is excluded from that Item’s majority. It is not counted as a Pass or a Fail. An Item recorded as Not observed is excluded from the majority, the same as Not completed. The summary states how many agents completed the check for each Item, and always states how many agents were tested. |
| cross-agent summary | delegation adds no independent vote | A delegated result adds no independent vote — only the originator’s result counts in that Item’s majority. Delegation that happens invisibly in the background is not recorded and does not change the observation. |
| cross-agent summary | no averaging of recommendation positions | No average, no combined rank, without a defined method. |
| cross-agent summary | common deficiency / agent-specific problem | Common deficiency — an Item that fails the majority rule. Agent-specific problem — an Item that fails for one agent but passes the majority rule. Fixes are prioritized by how many tested agents found the issue, then by AI Sharc grade impact (Spec §8.1). |
| storage rules | one database for all agents | Agents are distinguished by the vendor, product, and agent\_label on each record, not by a store. |
| storage rules | a re-run is a new observation | Uniqueness is (vendor, product, agent\_label, query\_id, checked\_at) for agent\_runs; a re-run at a different time inserts a new run and never overwrites the old one — the same rule as audits. Loading the same run twice is a no-op, never a second run. agent\_run\_firms is UNIQUE on (run\_id, position) and on (run\_id, name\_as\_given); agent\_observation\_rows is UNIQUE on (run\_id, check\_id). |
| storage rules | observation tables never enter the scored tables | They do not enter audit\_rows, and the audit\_summary view is unchanged (it derives from audit\_rows only). Per-agent observations never change the AI Sharc grade. |
| storage rules | files stay as the audit trail | The Agent Validation record remains the human-readable record, and the observation files and transcripts stay as the evidence a reviewer can re-open; the database tables are the system of record the aggregation layer queries. |
